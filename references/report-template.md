# 报告模板

```markdown
# 需求就绪度评估：<文档名>

> 评估日期：YYYY-MM-DD ｜ 全文 N 字，有效内容约 M 字（X%）

## 结论

**总分 NN / 100 ｜ <可进入评估 / 补充后评估 / 建议退回>**

一句话：<这份需求最大的问题是什么>

| 维度 | 得分 | 一句话 |
|---|---|---|
| 痛点与背景 | /35 | |
| 用户场景四要素 | /30 | |
| 痛点和诉求对得上 | /10 | |
| 精简度 | /25 | |

门槛项：G1 ✅ G2 ✅ G3 ❌ G4 ✅（不过的写原因）

结论分档：≥75 可进入评估；60–74 补充后评估；<60 或门槛不过 → 建议退回。

## 一页摘要（替你读完了原文）

- **要解决的问题**：
- **谁在用**：
- **关键场景**：
- **业务想要的结果**：
- **业务给的规则/口径**（产品直接采用）：
- **业务期望的方案**（仅参考）：
- **范围**：涉及哪些模块/环节

## 各维度说明

### 痛点与背景 NN/35
- ✅ 做得好的（引原文）
- ❌ 缺的（引原文位置 + 为什么扣）

（其余三维同样格式）

## 内容构成

| 类别 | 字数 | 占比 | 对应章节 |
|---|---|---|---|

## 矛盾与问题

1. **<类型>**：§x.x 写"…"；§y.y 写"…"。<冲突在哪>

## 红旗信号

- <信号>：<依据>

## 追问清单（可直接转给业务）

> 以下问题请补充后再进入评估，越具体越好，有数据给数据，没数据举个真实例子。

1. （§2.2）你提到"审批流程太慢"，具体慢在哪一步？最近一个月平均要多久？能举一两个例子吗？
2. …

（按重要程度排，痛点类在前，矛盾类在后，一般 5–10 条）

---
下次可以参考这份一页纸模板来写：`templates/一页纸需求模板.md`（本 skill 目录下）
```
